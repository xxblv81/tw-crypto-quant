# 大戶持股變動（集保股權分散表，2026-09-07）

**結論：訊號是真的，但只做成「警示旗標」，不進分數。**
理由是樣本只有一年、188 筆，而且訊號不對稱 —— 減持要避開，增持沒有明顯加分。

工具：`taiwan/python/tdcc.py`

## 一、資料：能拿到什麼、拿不到什麼

| 來源 | 涵蓋 | 成本 |
|---|---|---|
| opendata `getOD.ashx?id=1-5` | **只有最新一週**，全市場 3,539 檔 | 1 個請求 |
| 官網查詢 `qryStock` | **51 週**（2025-09-12 ~ 2026-09-04） | 逐檔逐週，需 CSRF token |

實測 opendata 完全不吃日期參數（`date` / `scaDate` / `sd` 都試過，一律回最新週）。
大戶定義 = 400 張以上 = 持股分級 12~15，已與官網表格對照無誤（台積電 87.49%）。

### ★★ 抓取時踩到的兩個坑（都已修，寫下來免得重犯）

1. **`SYNCHRONIZER_TOKEN` 是一次性的。** 同一個 token 送第二次查詢會回空表，
   而且 **HTTP 仍是 200、不報錯** —— 靜默失效。
   初版每 200 次才換一次 token，5,350 次請求只抓到「每週 1 檔」。
   實測：同 token 連三次 → `(17,6) / None / None`；每次換 token → 三次全中。
   → **每筆查詢前都要重新 GET 表單拿 token**，成本是 2 個請求換 1 筆資料。
2. **長時間爬蟲必須容忍網路瞬斷。** 第二次跑到 13/51 週時被
   `ChunkedEncodingError` 整個打斷。已加指數退避重試，並改成**每 20 檔即時落地**
   （原本一週跑完才存，中途掛掉整週白做）。

★ 只用「進場當下已公布」的週別 —— 集保次週才公布，取 6 天時滯，實測資料延遲中位 10 天。

## 三、為什麼只做旗標、不進分數

| 理由 | 說明 |
|---|---|
| **樣本只有 188 筆、單一年份** | 而且 2025-09~2026-09 是多頭年（同期基準 PF 2.031 vs 全期 1.715） |
| **多重比較** | 我測了週變動／4 週變動／水準值 × 多種分桶數，第 1 百分位未做多重比較校正 |
| **訊號不對稱** | 增持側只有 2.421 vs 基準 2.031，加分很弱。它是排除條件不是排序變數 |
| **前例** | `align` 分項在高分區恆為 10（沒鑑別力）、投信連買測完只值 0.15 權重 —— 新資料不先驗證就進分數會出事 |

實作：執行表加 `大戶%`、`大戶Δ` 兩欄，週變動 < −0.25pp 標 `⚠ 大戶減持`。
**不擋進場、不影響分數**，由人判斷。

## 四、要能真正驗證，得從現在開始存

官網只保留 51 週滾動視窗，**不自己存就永遠只有一年**。
`tdcc.py --latest` 只要 1 個請求，已加進 `台股工具.command` 選項 1 與 10 的快取更新 ——
日常選股就會順便累積。**兩三年後**才會有足夠樣本把它升級成計分項（或推翻它）。

```bash
cd taiwan/python
./.venv/bin/python tdcc.py --latest      # 每週一次，1 個請求
./.venv/bin/python tdcc.py --status
```
